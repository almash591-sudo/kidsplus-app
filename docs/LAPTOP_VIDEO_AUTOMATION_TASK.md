# Задание ноутбучной сессии Codex: автоматическая проверка YouTube-видео для KidsPlus

Прочитай задание и продолжай без ручного просмотра роликов пользователем. Цель — выяснить и, если это технически и лицензионно возможно, собрать локальный конвейер, который сам проверяет содержание видео, выбирает полезный фрагмент и готовит контрольный тест.

## Контекст

- Основная копия KidsPlus находится на другом компьютере. Работай в отдельной локальной копии и собственной ветке; передавай результат через Git или отдельными отчётами.
- Ноутбук: NVIDIA RTX 3060 с 6 ГБ VRAM. Сейчас на нём работает локальная генерация изображений, но это не означает, что установленная модель понимает видео или звук.
- Основная сессия подготовила список 21 кандидата в `docs/video-review-candidates.json` и доску `docs/video-review-board.html`. Доска не является автоматическим анализатором. В ней YouTube embed выдаёт ошибку 153, потому что HTML открыт как `file://` и плеер не получает HTTP Referer.
- В KidsPlus уже есть автоматический moderation worker: он передаёт модели публичный YouTube URL без скачивания и получает сегменты и вопросы. Сейчас очередь остановлена ответом `Gemini 402` — исчерпаны кредиты. Пользователь просил искать способ без ручного просмотра и без повторного запуска Gemini.
- Пользователь не хочет скачивать видео; ребёнку должен показываться выбранный отрезок, затем приложение проверяет усвоение коротким тестом.

## Требуемая работа

1. Проверь фактическую конфигурацию ноутбука: ОС, свободную VRAM, ComfyUI, установленные локальные модели и возможность локального inference. Не выводи секреты и не меняй существующие настройки генерации изображений.
2. Изучи актуальные официальные правила и API YouTube для embedded playback, captions и доступа к видеоданным. В отчёте укажи конкретные источники.
3. Найди реалистичную локальную multimodal-модель, которая может анализировать и изображение, и речь/звук на 6 ГБ VRAM, либо объясни, почему это ограничение невыполнимо. Не устанавливай большие модели и зависимости до оценки размера, требований и лицензии.
4. Проверь, можно ли по документированному и разрешённому YouTube-интерфейсу передавать живой playback локальной модели, **не скачивая, не копируя, не кэшируя и не сохраняя** аудиовизуальное содержимое. Не используй `yt-dlp`, `youtube-dl`, неофициальные transcript/caption API, reverse engineering, обходы Referer/региональных ограничений или запись потока.
5. Если такой путь действительно доступен, сделай локальный proof-of-concept на одном видео из JSON. На выходе для видео нужны: краткое содержание, оценка соответствия возрастам 2 и 5 лет, замечания о потенциально неподходящем содержании, один выбранный непрерывный фрагмент длиной 1–5 минут с точными `startSec`/`endSec`, тема и минимум 3 вопроса с 4 вариантами и одним проверенным правильным ответом. Укажи доказательства по временным меткам и confidence.
6. Если официального пути к аудио/видео содержимому нет, остановись до любого обходного решения. Подготовь отчёт с точным блокером и минимальными допустимыми альтернативами: источник с лицензированными локальными файлами; разрешённый облачный видео-анализатор; либо восстановление существующего прямого YouTube URL-анализатора KidsPlus. Не выдавай анализ по одним заголовкам/thumbnail за просмотр.
7. Не меняй production, не отправляй массовые ролики в очередь, не назначай материалы детям, не трать деньги на API и не включай платные тарифы. Результат — локальный POC или конкретный отчёт о блокере и передаваемый JSON.

## Критерий завершения

Автоматизация считается доказанной только если локальная модель сама получила доступ к аудио и визуальному содержимому допустимым способом, выбрала временные границы, а вопросы соответствуют фактически просмотренному фрагменту. Если это невозможно при текущих ограничениях — вернуть отчёт о блокере и перечислить, какое одно ограничение нужно снять для полноценной автоматизации.
