# ТЗ: образовательная контент-система для детей 2–6 лет

Рабочее название: **KidLearn** (можно переименовать).

## 1. Проблема и цель

Родитель включает ребёнку хороший мультфильм на YouTube, а через время ребёнок уже смотрит случайный низкокачественный контент — его туда приводят рекомендации и автопроигрывание. Цель проекта — закрытая среда, где ребёнок видит **только заранее одобренный родителем контент**, выстроенный по учебному плану, с чередованием видео и интерактивных заданий, лимитами времени и аналитикой.

Ключевые принципы:

- Ребёнок не может выйти за пределы одобренного контента: нет поиска, рекомендаций, автоплея чужих видео, внешних ссылок.
- Весь контент проходит модерацию: ИИ-предмодерация (Claude) + обязательное финальное одобрение родителем.
- Видео не скачиваются: используются встраиваемые плееры с ограничением фрагмента (start/end).
- Пассивный просмотр чередуется с активностью (квизы, карточки, интерактивы).
- Персональные данные ребёнка хранятся только в собственной БД проекта (хостинг Railway, см. раздел 3) и не передаются в LLM и другие внешние сервисы. Объём персональных данных минимален.

## 2. Пользователи и интерфейсы

| Интерфейс | Кто | Форма |
|---|---|---|
| Детский (киоск) | Ребёнок 2–6 лет | PWA в полноэкранном режиме на телефоне/планшете + режим киоска (см. раздел 8) |
| Родительский | Родитель | Веб-интерфейс, устанавливаемое PWA, адаптивный (телефон + ПК) |
| Сервер | — | Облачный хостинг Railway (решение владельца проекта от 2026-10-06; изначально планировался домашний ПК) |

Поддержка нескольких детей (профили) и нескольких устройств с первой версии на уровне модели данных.

**Исходная конфигурация:**
- Несколько детей 2–6 лет. У каждого свой профиль, учебный план, лимиты и аналитика.
- Два одинаковых телефона Samsung Galaxy S20+ (Android 13, One UI 5.x, экран 6,7″, 1440×3200). Каждое устройство закреплено за одним ребёнком.
- Детский интерфейс оптимизировать и тестировать в первую очередь под этот экран, в портретной и альбомной ориентации.

## 3. Технологический стек (предлагаемый)

- **Монорепозиторий** pnpm workspaces, TypeScript везде.
  - `apps/api` — бэкенд: Node.js 22 LTS, Fastify, Zod для валидации.
  - `apps/worker` — фоновые задачи (модерация, генерация квизов, TTS, проверка доступности видео).
  - `apps/kid` — детское PWA: React + Vite.
  - `apps/parent` — родительское PWA: React + Vite, библиотека компонентов (например, shadcn/ui или Mantine).
  - `packages/shared` — общие типы, Zod-схемы, константы.
  - `packages/providers` — адаптеры внешних сервисов (видео, TTS, LLM, картинки).
- **БД:** PostgreSQL 16, ORM Drizzle, миграции в репозитории.
- **Очередь задач:** pg-boss (работает поверх PostgreSQL, без Redis).
- **Реалтайм** (удалённое управление сессией ребёнка): Server-Sent Events или WebSocket.
- **Хранение медиа** (озвучка, картинки): через адаптер хранилища; локально — файловая система, в продакшене — хранилище, доступное и api, и worker. Отдача через API с кэшированием.
- **Развёртывание (решено 2026-10-06):** Railway, регион EU West (Амстердам) — отдельные сервисы api, worker, веб (PWA), managed PostgreSQL; автодеплой из GitHub. Docker Compose используется для локальной разработки. Ночной бэкап `pg_dump` + медиа.
- **Доступ извне:** HTTPS обеспечивает Railway (домены `*.up.railway.app` или свой домен). Tailscale/Cloudflare Tunnel не нужны.
- **Тесты:** Vitest (unit/интеграция), Playwright (e2e детского сценария и модерации).
- **CI:** GitHub Actions — lint, typecheck, tests на каждый push.

Если Claude Code видит веские причины изменить стек — предложить и обосновать до начала работы, не менять молча.

## 4. Предметная модель

Основные сущности (имена — ориентир):

- `ParentUser` — родитель (email + пароль, позже passkey).
- `Child` — профиль: прозвище вместо настоящего имени, месяц и год рождения (без точной даты), грамматический род для русских фраз озвучки («ты справилась» / «ты справился»), языки, настройки сложности.
- `Device` — привязанное детское устройство (токен устройства, привязка через QR-код из родительского интерфейса).
- `Subject` — предмет: математика, английский, китайский, русский язык, окружающий мир и т.д. (пользовательский список).
- `Curriculum` — учебный план для ребёнка на период (например, 3 месяца).
- `CurriculumWeek` / `Topic` — темы по неделям внутри предмета (например, «Счёт до 5», «Цвета на английском»).
- `DailySchedule` — правила дня: сколько предметов (по умолчанию 3), минут на предмет (по умолчанию 20), разрешённые временные окна, дни недели.
- `Lesson` — урок по теме: упорядоченная последовательность блоков.
- `LessonBlock` — блок урока одного из типов: `video_segment`, `flashcards`, `quiz`, `interactive`.
- `VideoSource` — исходное видео (провайдер, внешний ID, метаданные, статус доступности).
- `VideoSegment` — фрагмент видео: start/end в секундах, длительность 1–5 минут, тема, возраст, язык.
- `Flashcard` — картинка + текст для озвучки + аудиофайл.
- `Quiz` / `Question` / `AnswerOption` — вопрос с озвучкой и 4 вариантами-картинками (один верный).
- `MediaAsset` — картинка или аудио (источник, лицензия, хэш, путь).
- `ModerationReport` — результат ИИ-проверки + решение родителя.
- `Session` — сессия ребёнка за день/предмет.
- `Event` — события для аналитики (старт блока, ответ, время ответа, пропуск, выход из приложения).
- `LlmUsage` — учёт токенов Claude по задачам.

## 5. Детский интерфейс (киоск)

### 5.1. Общие требования UX для 2–6 лет

- Никакого текста как основного способа навигации: иконки, крупные картинки, голосовые подсказки.
- Зоны нажатия крупные (минимум ~1/4 экрана для вариантов ответа).
- Нет таймеров с давлением, нет наказывающих звуков. Ошибка — мягкая подсказка.
- Нет бесконечной ленты и автоплея за пределами плана.
- Спокойный финальный экран «На сегодня всё» с прощальной озвучкой.
- Выход из детского режима и доступ к настройкам — только по родительскому PIN (с «взрослым» жестом: удержание угла экрана 3 секунды → ввод PIN).
- Работает в Chrome на Android 10+ и Safari на iOS 16+; первая загрузка < 3 с на среднем Android.

### 5.2. Сценарий дня

1. Устройство открывает детское PWA и сразу входит в профиль ребёнка, за которым оно закреплено. Экрана выбора ребёнка нет, поэтому сёстры не могут переключиться на чужой профиль.
2. Экран «Сегодня»: 3 большие иконки предметов из расписания дня. Пройденные помечаются (звёздочка/наклейка).
3. Ребёнок выбирает предмет (или порядок задан родителем) → запускается урок.
4. Урок — последовательность блоков. Базовый цикл: **видео (1–5 мин) → квиз из 5 вопросов → следующее видео → …**, между ними могут быть карточки с озвучкой и интерактивы.
5. Когда время предмета (20 мин) исчерпано: текущий блок досматривается/доигрывается, новый блок не начинается. Похвала → возврат на экран «Сегодня».
6. Когда исчерпан дневной лимит или вышло разрешённое временное окно — экран «На сегодня всё». Продолжение только если родитель добавил время удалённо.

### 5.3. Видеоплеер

- Встраиваемый плеер провайдера через JS API (для YouTube — IFrame Player API, домен `youtube-nocookie.com`).
- Параметры YouTube: `start`, `end`, `controls=0`, `disablekb=1`, `fs=0`, `playsinline=1`, `rel=0`, `iv_load_policy=3`, `enablejsapi=1`, `origin`.
- **Прозрачный оверлей поверх iframe**, перехватывающий все касания: ребёнок не может нажать на логотип, название, подсказки или конечные заставки. Свои крупные кнопки «пауза/продолжить» поверх оверлея.
- Окончание фрагмента контролирует наше приложение: по событию API (время ≥ end или состояние ENDED) плеер немедленно скрывается/уничтожается, до того как провайдер покажет рекомендации. Дополнительно — опрос `getCurrentTime()` раз в 250 мс как страховка.
- Если видео недоступно (удалено, ошибка встраивания, регион) — блок пропускается, событие логируется, родитель получает уведомление.
- При сворачивании приложения/блокировке экрана — пауза и остановка учёта времени.

### 5.4. Квиз

- Экран делится на 4 равные зоны (сетка 2×2), в каждой — картинка-вариант. Один вариант верный.
- Вопрос озвучивается автоматически при показе; крупная кнопка «ушко» повторяет вопрос.
- Касания игнорируются, пока звучит вопрос (минимум первые ~1 с), — защита от случайных нажатий.
- Верный ответ: анимация + озвученная похвала → следующий вопрос.
- Неверный ответ: мягкая озвучка «Попробуй ещё», неверный вариант затухает; ребёнок пробует снова, пока не выберет верный.
- После 5 вопросов, на которые дан верный ответ, открывается следующий блок (видео).
- Для аналитики фиксируется: верно с первой попытки или нет, число попыток, время до ответа.
- Защита от «тыканья наугад»: если 3 неверных касания подряд быстрее 1 с — пауза, повтор вопроса.
- Количество вариантов и вопросов настраивается в профиле. Значения по умолчанию задаются по возрасту, родитель может их изменить:

| Параметр | 2 года | 5 лет |
|---|---|---|
| Вариантов ответа | 2 | 4 |
| Вопросов до следующего видео | 3 | 5 |
| Предметов в день | 2 | 3 |
| Минут на предмет | 10–15 | 20 |
| Длительность видеофрагмента | 1–3 мин | 1–5 мин |
| Тип вопросов | «Где кошка?», цвет, форма, звук животного | счёт, буквы, слова на иностранном языке, логика |

- При переходе ребёнку в следующую возрастную группу система предлагает родителю обновить настройки.

### 5.5. Карточки с озвучкой

- Полноэкранная картинка + озвучка слова/фразы, листание свайпом или крупной стрелкой. Повтор озвучки по нажатию на картинку.
- Для языковых предметов — озвучка на целевом языке, опционально с переводом на русский.

### 5.6. Интерактивы (этап 7, задел в архитектуре)

Тип блока `interactive` с плагинной архитектурой: каждый вид интерактива — компонент + JSON-схема параметров. Примеры: перетащи предмет в корзину, посчитай и нажми цифру, найди пару, собери слово/иероглиф по частям, раскраска по цвету с озвучкой цвета.

## 6. Родительский интерфейс (PWA)

### 6.1. Разделы

1. **Дети** — профили, возраст, языки, настройки сложности.
2. **Учебный план** — создание плана на период (по умолчанию 3 месяца): выбор предметов, распределение тем по неделям, расписание дня (3 предмета × 20 мин по умолчанию), разрешённые дни и временные окна. Кнопка «Сгенерировать черновик плана» (Claude предлагает темы по возрасту и целям, родитель редактирует).
3. **Библиотека контента** — все видеофрагменты, карточки, квизы с фильтрами (предмет, тема, возраст, язык, статус).
4. **Добавление контента** — вставка ссылки на видео / канал / плейлист, поиск по запросу через API провайдера, белый список доверенных каналов.
5. **Очередь модерации** — карточки на проверку: превью фрагмента прямо в интерфейсе (с заданными start/end), отчёт ИИ, предложенные фрагменты и вопросы. Действия: одобрить / отклонить / поправить таймкоды / отредактировать вопросы и картинки.
6. **Уроки** — конструктор урока: drag-and-drop блоков, автосборка урока по теме из одобренного контента.
7. **Управление сейчас** — что ребёнок делает в данный момент, кнопки «пауза», «завершить», «+10 минут».
8. **Аналитика** — см. раздел 9.
9. **Устройства** — привязка детского устройства по QR-коду, отзыв доступа.
10. **Настройки** — PIN детского режима, лимиты, уведомления, бюджет токенов Claude, ключи API (только отображение статуса, сами ключи в `.env`).

### 6.2. Уведомления

Web Push: «модерация готова к проверке», «ребёнок закончил занятия», «видео стало недоступно», «приближается лимит токенов».

## 7. Модерация и генерация контента

### 7.1. Конвейер для видео

1. Родитель добавляет ссылку / канал / поисковый запрос.
2. Сбор метаданных через официальный API провайдера (для YouTube — Data API v3, `videos.list`): название, описание, канал, длительность, `madeForKids`, `embeddable`, региональные ограничения, теги, превью.
3. Отсев на входе: не встраивается, недоступно в регионе, длительность вне разумных пределов.
4. Получение субтитров, если доступны (см. раздел 12 о рисках).
5. Анализ Claude (структурированный JSON-ответ по схеме):
   - соответствие возрасту (2–3, 4–5, 6 лет);
   - образовательная ценность и соответствие теме плана;
   - красные флаги: пугающее, насилие, грубая лексика, распаковки игрушек и реклама, кликбейт, гиперстимуляция (слишком быстрый монтаж, крики), ошибки в материале, неправильное произношение для языковых уроков;
   - предложенные фрагменты 1–5 минут с таймкодами (по субтитрам) и привязкой к теме;
   - черновик 5–10 вопросов квиза по каждому фрагменту: текст вопроса для озвучки, 4 варианта с описанием нужной картинки, верный ответ.
6. Превью-картинки (thumbnails) можно передавать Claude как изображения для дополнительной проверки.
7. Результат попадает в очередь модерации родителя. **До детей доходит только одобренное родителем.**
8. Периодическая (ежедневная) проверка доступности одобренных видео.

### 7.2. Картинки для квизов и карточек

Адаптер `ImageProvider` с несколькими источниками:
- SVG, сгенерированные Claude: цифры, фигуры, буквы, цвета, иероглифы, простые схемы — основной источник для математики и языков.
- Открытые наборы иконок/эмодзи с совместимой лицензией (например, OpenMoji, Twemoji) — с хранением атрибуции.
- Стоковые API с открытой лицензией (например, Pixabay) — с модерацией родителем.
- Загрузка своих картинок родителем.
- Позже — генерация изображений (например, YandexART), если понадобится.

Каждый `MediaAsset` хранит источник и лицензию.

### 7.3. Озвучка (TTS)

- Адаптер `TtsProvider`. **Решено 2026-10-07:** пока озвучивает сам телефон ребёнка — синтез речи браузера (Web Speech API, голос Samsung/Google TTS на устройстве); сервер аудио не создаёт. Серверная озвучка через Google Cloud Text-to-Speech реализована и включается переменной `TTS_PROVIDER=google` (поддерживает ru, en и китайский `cmn-CN`); Yandex SpeechKit можно подключить через тот же адаптер. Кэш ниже относится к серверной озвучке.
- Кэш: аудио генерируется один раз и хранится на диске, ключ — хэш (текст + язык + голос + скорость).
- Медленная и чёткая подача для малышей (настройка скорости).
- Китайский язык — через Google TTS; дополнительно родитель может загрузить свою аудиозапись.

### 7.4. Использование Claude API

**Решено 2026-10-09 (владелец):** вместо Claude API — Google Gemini. Модель сама смотрит публичное видео YouTube по ссылке (картинка и звук), поэтому субтитры не нужны. Модель — `gemini-3.8-flash` (переменная `LLM_MODEL_MAIN`). В разделах 7 и 11 «Claude» читать как «языковая модель»; остальные требования (строгий JSON по схеме, повтор, учёт токенов и лимиты, без персональных данных, версионируемые промпты) — в силе.

- Адаптер `LlmProvider`; модели задаются в `.env` (например, `CLAUDE_MODEL_MAIN=claude-sonnet-5-5` для модерации и генерации, `CLAUDE_MODEL_FAST=claude-haiku-4-5-20251001` для быстрой первичной фильтрации).
- Все ответы — строгий JSON по Zod-схеме, с повтором при невалидном ответе.
- Учёт токенов по каждой задаче в `LlmUsage`, дневной и общий лимит (общий бюджет 100 млн токенов), остановка очереди при превышении и уведомление родителю.
- В промпты **не передаются** имя ребёнка и другие персональные данные — только возраст и тема.
- Промпты хранятся в репозитории как версионируемые шаблоны (`packages/providers/prompts/`).

## 8. Режим киоска

Детское PWA само по себе не может заблокировать телефон, поэтому киоск строится поэтапно:

Целевые устройства: 2 × Samsung Galaxy S20+ (Android 13, One UI 5.x). iOS не поддерживается.

- **Этап 1 (без разработки):** PWA ставится через Chrome («Добавить на главный экран») и открывается в полноэкранном режиме. Сверху включается системная функция Samsung «Закрепление окон» (One UI: Настройки → Биометрия и безопасность → Другие параметры безопасности → Закрепление окон; путь может немного отличаться). В ней обязательно включить «Запрашивать PIN-код перед откреплением». Выход: одновременно удерживать «Назад» и «Недавние». Пошаговая инструкция со скриншотами — в родительском интерфейсе (раздел «Устройства»).
- **Этап 6 (своя обёртка для Android):** нативная оболочка (Capacitor) с WebView детского PWA, работающая как Device Owner в режиме Lock Task. Она блокирует кнопки «Домой» и «Недавние», строку состояния, уведомления и установку приложений. Выход — только по PIN.
  - Провижининг: `adb shell dpm set-device-owner <пакет>/.AdminReceiver`. На момент команды на телефоне не должно быть аккаунтов (Google, Samsung), иначе команда откажет. Проще всего — сброс к заводским настройкам и провижининг до добавления аккаунтов; аккаунты можно добавить после.
  - Скрипт провижининга (`scripts/provision-device.sh`) выполняется для каждого из двух телефонов и привязывает устройство к профилю ребёнка.
  - Скрипт снятия Device Owner — для возврата телефона в обычный режим.
  - Обновление оболочки — через сборку APK и `adb install`, публикация в магазине не требуется.
  - Учесть энергосбережение One UI: добавить приложение в исключения оптимизации батареи, чтобы система не выгружала его в фоне.
- Детское приложение не содержит ссылок наружу; CSP запрещает навигацию на внешние домены, кроме iframe провайдеров видео.

## 9. Аналитика

- По ребёнку и предмету: время за день/неделю, пройденные уроки и темы, прогресс по плану.
- Квизы: точность с первой попытки по темам и навыкам, среднее время ответа, темы с повторяющимися ошибками.
- Видео: досмотры, пропуски, недоступные видео.
- Рекомендации для родителя (генерирует Claude по агрегированным, обезличенным данным): какие темы повторить, где ребёнку слишком легко.
- Еженедельный отчёт (экран + push).
- Темы с низкой точностью автоматически получают повторение в следующих уроках (простое правило интервального повторения).

## 10. Нефункциональные требования

- **Безопасность:** хэширование паролей (argon2), сессии с httpOnly-cookie, токены устройств с возможностью отзыва, rate limiting на вход, CSP, все секреты только в `.env` (в `.gitignore`), `.env.example` в репозитории.
- **Приватность:** данные детей хранятся только в БД проекта на Railway; сервер публично доступен, поэтому аутентификация, токены устройств и rate limiting обязательны на всех эндпоинтах.
- **Надёжность:** ночной бэкап БД и медиа, ротация бэкапов (7 дневных + 4 недельных), автоперезапуск сервисов.
- **Ресурсы:** вся система должна укладываться в ~4 ГБ RAM суммарно; следить за стоимостью на Railway.
- **Логи:** структурированные (pino), без персональных данных.
- **Локализация:** интерфейс родителя на русском; архитектура i18n заложена.

## 11. Этапы разработки и критерии приёмки

Каждый этап — отдельная ветка и PR, тесты проходят в CI, обновлён `PROGRESS.md`.

**Этап 0 — каркас.** Монорепо, Docker Compose для локальной разработки, БД и миграции, CI, `.env.example`, деплой на Railway.
✅ Push в `main` разворачивает все сервисы на Railway; открываются заглушки обоих PWA по HTTPS; `/api/health` подтверждает связь с БД.

**Этап 1 — плеер и ручной контент.** Вход родителя, профили детей, привязка устройства по QR, ручное добавление видео со start/end, детский плеер с оверлеем и контролем окончания фрагмента.
✅ Ребёнок видит только добавленные фрагменты; после окончания фрагмента никакие рекомендации YouTube не видны; касания по iframe не проходят.

**Этап 2 — квизы, карточки, озвучка.** Ручное создание квизов и карточек, TTS с кэшем, логика «5 верных ответов → следующее видео».
✅ Полный цикл видео → квиз → видео работает на телефоне; озвучка повторно не генерируется.

**Этап 3 — модерация через Claude.** Конвейер из раздела 7.1, очередь модерации, генерация квизов и SVG-картинок, учёт токенов.
✅ По ссылке на видео через несколько минут в очереди появляется отчёт с фрагментами и черновиком квиза; без одобрения родителя контент ребёнку недоступен.

**Этап 4 — учебный план и расписание.** План на период, генерация черновика плана, расписание дня, лимиты, временные окна, автосборка уроков, экран «Сегодня», удалённое управление.
✅ Ребёнок получает ровно 3 предмета по 20 минут по плану; лимиты соблюдаются, учёт времени ведётся на сервере.

**Этап 5 — аналитика.** Дашборды, еженедельный отчёт, push-уведомления, повторение слабых тем.

**Этап 6 — Android-киоск.** Обёртка Capacitor с Lock Task Mode, скрипты провижининга и снятия, инструкция.
✅ На обоих S20+ ребёнок не может выйти из приложения кнопками, жестами или через шторку уведомлений; выход только по PIN; после перезагрузки телефон сразу открывает детский режим.

**Этап 7 — расширение.** Интерактивы (плагины), дополнительные видеопровайдеры, новые типы блоков.

Этапы 8–11 добавлены владельцем 2026-10-10 (телефон ребёнка — его единственное устройство: без симкарты, в детском режиме).

**Этап 8 — заряд батареи.** Значок заряда в детском приложении (процент, зарядка); голосовые напоминания поставить телефон на зарядку — на 20, 10 и 5 %, не прерывая видео и квиз; «Телефон заряжается» при подключении. Заряд телефона виден родителю в кабинете, при 15 % — push.
✅ На телефоне ребёнок видит заряд; напоминание звучит один раз на каждый порог за разряд; родитель видит заряд и получает push.

**Этап 9 — камера.** Своя камера внутри киоска (системная выводит из детского режима): фото по одному касанию без серийной съёмки (пауза между снимками), видео не длиннее 30 секунд (останавливается само); галерея в детском приложении; копия снимков — в кабинете родителя (хранятся на сервере KidsPlus, в модели и другие сервисы не передаются).
✅ Серийная съёмка невозможна; видео обрывается на 30 секундах; снимки видны в кабинете.

**Этап 10 — звонки.** Видео- и аудиозвонки между четырьмя устройствами семьи (2 детских телефона, 2 родительских) — WebRTC, сервер KidsPlus только соединяет, при необходимости — ретранслятор TURN (звук и видео зашифрованы и ретранслятору недоступны). У ребёнка — портреты родных вместо номеров, звонить можно только семье и только в окно дня; входящий родителю — push, ребёнку — на весь экран; групповой звонок до 4 участников.
✅ Звонок ребёнок ↔ родитель и ребёнок ↔ сестра проходит через VPN телефона; чужие позвонить не могут.

**Этап 11 — радионяня.** Родитель из кабинета включает передачу звука с телефона ребёнка (только звук, один в одну сторону); на телефоне виден значок микрофона; работает при выключенном экране; шум выше порога — push родителю.
✅ Родитель слышит комнату при погашенном экране телефона ребёнка; при плаче приходит push.

**Этап 12 — новый дизайн** (добавлен владельцем 2026-10-10). Современный светлый стиль в духе iOS: детское приложение (12а) и кабинет родителя с тёмной темой (12б); анимации, звуки, вибро-отклик; шрифты — внутри приложений.
✅ Владелец принимает вид на телефонах; e2e не ломаются.

**Этап 13 — Кабинет 2.0** (добавлен владельцем 2026-10-11). Кабинет вокруг детей и ежедневных дел, прежде всего для телефона: 5 вкладок — Главная («Нужно ваше внимание», карточки детей с быстрыми действиями, новые снимки), Контент (видео, карточки, игры и проверка видео в одном месте; одобрение одним касанием — детям по возрасту из отчёта модели), План, Прогресс, Ещё.
✅ Ежедневные дела делаются с «Главной» в одно-два касания; владелец принимает удобство на телефоне.

## 12. Риски и открытые вопросы

- **Доступность YouTube.** Если YouTube работает медленно или нестабильно в регионе пользователя, это скажется и на детском плеере. Поэтому видеоплеер реализуется через адаптер `VideoProvider` (YouTube первым), с возможностью добавить RuTube, VK Видео и другие. Для каждого провайдера проверить: встраивание, параметр начала фрагмента, JS API для контроля времени и окончания.
- **Реклама во встраиваемых видео.** В видео YouTube для детей может показываться реклама, отключить её через плеер нельзя. Учитывать при выборе каналов; при модерации отмечать каналы, где это мешает.
- **Субтитры.** Официальное скачивание субтитров через YouTube Data API доступно только владельцу видео. Неофициальные способы получения субтитров нарушают или находятся на грани условий YouTube — решение принимает владелец проекта. Без субтитров модерация опирается на метаданные и превью, а таймкоды фрагментов выставляет родитель.
- **Видео не скачиваются** — это требование, а не ограничение реализации.
- **Квота YouTube Data API** — 10 000 единиц в день по умолчанию; `search.list` стоит 100 единиц, `videos.list` — 1. Кэшировать метаданные, поиск использовать экономно.
- **Модель может ошибаться** — Gemini смотрит видеоряд и звук, но может пропустить пугающее или рекламу. Поэтому финальное одобрение родителем обязательно.
- **Решено:** детские устройства — 2 × Samsung Galaxy S20+ (Android), iOS не нужен.
- **Android 13 — последнее крупное обновление для S20+.** Это не мешает проекту, но новые функции браузера и системы, требующие Android 14+, не использовать.
- **Открытый вопрос:** нужен ли в будущем доступ для других семей (многопользовательский режим) — влияет на модель доступа и хостинг.
